# ROADMAP.md — Karasu Buyers Club

**نسخه سند:** 1.0.0
**پیش‌نیاز مطالعه:** PRD.md، ARCHITECTURE.md، GUIDELINES.md

هر فاز باید طبق قوانین `AGENTS.md` پیش از شروع، پوشه `docs/` رو کامل چک کنه، برنامه خودش رو در `docs/implementation-plan.md` ثبت کنه، و تسک‌ها رو در `docs/tasks.md` بشکنه. در پایان هر فاز: بامپ نسخه، ساخت زیپ، commit و push، و ریلیز گیت‌هاب.

---

## فاز ۰ — Setup اولیه (Bootstrap)

**هدف:** اسکلت فنی پروژه بدون هیچ قابلیت کسب‌وکاری

- ساخت ساختار پوشه‌بندی مطابق ARCHITECTURE.md
- فایل اصلی افزونه (`karasu-buyers-club.php`) با هدر استاندارد وردپرس + بررسی وابستگی WooCommerce
- تنظیم `composer.json` (PSR-4 autoload) و `package.json`
- پیکربندی Vite (دو بیلد admin/storefront) + Tailwind
- کلاس‌های پایه: `Plugin`, `Activator`, `Deactivator`
- تنظیم `phpcs.xml` (WPCS) و `eslint`/`prettier`
- اعلام سازگاری HPOS (حتی بدون منطق واقعی)
- راه‌اندازی Git repository + اولین commit + تگ نسخه `0.1.0`

**خروجی فاز:** افزونه در wp-admin فعال می‌شه بدون خطا، بدون هیچ رابط کاربری قابل مشاهده.

## فاز ۱ — لایه دیتابیس و موتور امتیازدهی هسته‌ای

**هدف:** منطق کسب‌وکار امتیاز، بدون UI

- پیاده‌سازی `Database\Schema` و اولین Migration (تمام جداول بخش ۳.۲ ARCHITECTURE.md)
- `PointsRepository` + `PointsEngineService`: امتیازدهی بر اساس مبلغ خرید (اتصال به `woocommerce_order_status_completed`)
- امتیازدهی بر اساس اکشن‌های اولیه: ثبت‌نام، اولین خرید
- منطق انقضای امتیاز (Cron + FIFO) — قابل فعال/غیرفعال (فلگ ذخیره می‌شه، حتی اگر UI تنظیمش بعداً بیاد)
- تست دستی: خرید تستی → بررسی صحیح ثبت رکورد در `kbc_points_ledger`

**خروجی فاز:** امتیاز به‌درستی در دیتابیس محاسبه و ثبت می‌شه؛ قابل بررسی از phpMyAdmin/WP-CLI.

---

## فاز ۲ — سطح‌بندی، کیف‌پول و مصرف امتیاز

**هدف:** تکمیل موتورهای اصلی باشگاه

- `TierRepository` + `TierService`: تعریف سطوح، محاسبه ارتقا بر اساس Lifetime Value، بدون تنزل
- `WalletRepository` + `WalletService`: شارژ/مصرف کیف‌پول، اتصال به چک‌اوت ووکامرس (`CheckoutWalletGateway`)
- `RedemptionService`: تبدیل امتیاز به تخفیف/ارسال رایگان/هدیه/کیف‌پول
- `CouponBridge`: ساخت کد تخفیف پویا از امتیاز مصرف‌شده
- تست دستی سناریوهای ارتقای سطح و مصرف امتیاز در چک‌اوت واقعی

**خروجی فاز:** یک مشتری تستی می‌تونه امتیاز کسب کنه، سطح ارتقا بگیره، امتیاز رو مصرف کنه، و از کیف‌پول در خرید بعدی استفاده کنه — همه از طریق کد/دیتابیس (هنوز بدون رابط بصری نهایی).

---

## فاز ۳ — معرفی دوست و مناسبت‌های خاص

- `ReferralRepository` + `ReferralService`: تولید کد معرف، ثبت رابطه، اعطای امتیاز دوطرفه، جلوگیری از سوءاستفاده
- `OccasionService`: فیلد تاریخ تولد در پروفایل (با پشتیبانی شمسی)، Cron بررسی روزانه مناسبت‌ها، اعمال پاداش تنظیم‌شده توسط ادمین

**خروجی فاز:** سیستم معرفی و مناسبت‌ها به‌صورت کامل و قابل تست عملیاتی هستن.

---

## فاز ۴ — اطلاع‌رسانی چندکاناله

- پیاده‌سازی `SMS_Provider_Interface` و سه Provider (Kavenegar، Mellipayamak، FarazSMS)
- `NotificationDispatcherService`: منطق مرکزی ارسال به کانال فعال (پیامک/ایمیل/داخلی)
- قالب‌های پیام Placeholder-based (ذخیره در `wp_options` یا جدول اختصاصی)
- `NotificationRepository` برای اعلان داخلی (پیش‌نیاز رابط React مشتری)
- Rate limiting روی مسیرهای پیامکی

**خروجی فاز:** رویدادهای کلیدی (کسب امتیاز، ارتقای سطح، تولد، معرفی موفق) پیامک/ایمیل/اعلان داخلی واقعی ارسال می‌کنن.

## فاز ۵ — REST API کامل

- پیاده‌سازی تمام Controller ها و route های بخش ۴.۲ ARCHITECTURE.md
- اعمال کامل `PermissionChecker` (nonce + capability) روی همه endpoint ها
- مستندسازی endpoint ها (حتی به‌صورت ساده در `docs/`)

**خروجی فاز:** لایه API کامل و امن، آماده مصرف توسط React.

## فاز ۶ — رابط کاربری مشتری (Storefront React)

- Bootstrap اپ React مشتری (`src/storefront`)
- کامپوننت‌های: خلاصه وضعیت (My Account tab)، داشبورد کامل باشگاه، تاریخچه، لیست پاداش‌ها، بخش معرفی دوست، مرکز اعلان
- اتصال کامل به REST API فاز ۵
- طراحی RTL با Tailwind، هماهنگ با هویت بصری Karasu

**خروجی فاز:** مشتری واقعی می‌تونه از my account یا صفحه اختصاصی، تمام وضعیت باشگاه خودش رو ببینه و امتیاز مصرف کنه.
