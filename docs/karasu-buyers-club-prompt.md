# پرامپت جامع افزونه Karasu Buyers Club

## ۱. معرفی کلی

**نام افزونه:** Karasu Buyers Club
**نوع:** افزونه باشگاه مشتریان مستقل برای WordPress + WooCommerce
**مدل توزیع:** مستقل، رایگان/فروش تکی (شبیه karasu-woo-pannel) — نه بخشی از یک تم
**معماری فنی:** کاملاً مشابه karasu-woo-pannel: PHP (بک‌اند وردپرسی) + Vite + React + Tailwind (فرانت‌اند هیدریت‌شده) + REST API اختصاصی وردپرس

هدف: ساخت یک سیستم کامل باشگاه مشتریان (Loyalty & Rewards) برای فروشگاه‌های ووکامرسی فارسی‌زبان، با امتیازدهی ترکیبی، سطح‌بندی مشتریان، کیف‌پول داخلی، معرفی دوست، و اطلاع‌رسانی چندکاناله.

---

## ۲. سیستم امتیازدهی (Points Engine)

### ۲.۱ مدل کسب امتیاز — ترکیبی
- **بر اساس مبلغ خرید:** نرخ تبدیل قابل تنظیم توسط ادمین (مثلاً هر X تومان = Y امتیاز)، قابل تعریف عمومی یا اختصاصی برای هر دسته/محصول
- **بر اساس اکشن‌های خاص:** امتیاز ثابت قابل تنظیم برای هرکدام از:
  - ثبت‌نام در سایت
  - اولین خرید
  - ثبت نظر (Review) برای محصول
  - تکمیل پروفایل
  - عضویت در خبرنامه
  - تولد و سالگرد عضویت (جزئیات در بخش ۵)
  - معرفی دوست (جزئیات در بخش ۴)
- موتور امتیازدهی باید ماژولار باشه تا در آینده اکشن‌های جدید بدون تغییر ساختار دیتابیس اضافه بشن (سیستم Hook/Trigger مبتنی بر اکشن‌های ووکامرس/وردپرس)

### ۲.۲ انقضای امتیاز (Expiry)
- **قابل فعال/غیرفعال از پنل ادمین**
- وقتی فعاله: تعیین بازه انقضا (مثلاً X ماه از تاریخ کسب) + امکان ارسال یادآوری قبل از انقضا
- وقتی غیرفعاله: امتیازات نامحدود باقی می‌مونن
- منطق انقضا باید FIFO باشه (قدیمی‌ترین امتیازها اول منقضی/مصرف بشن) و در گزارش مشتری قابل مشاهده باشه

### ۲.۳ مصرف امتیاز
- تبدیل امتیاز به کد تخفیف (یکبارمصرف یا درصدی روی سبد خرید)
- تبدیل امتیاز به ارسال رایگان
- تبدیل امتیاز به هدیه (محصول رایگان/انتخابی از لیست تعریف‌شده توسط ادمین)
- تبدیل امتیاز به شارژ کیف‌پول (کش‌بک — بخش ۳)
- **ادمین از پنل تعیین می‌کنه کدوم گزینه‌ها فعال باشن و نرخ تبدیل هرکدوم چقدر باشه**

---

## ۳. کیف پول داخلی (Internal Wallet)

- هر مشتری یک موجودی کیف‌پول داخلی داره (جدا از امتیاز، اما قابل شارژ از طریق تبدیل امتیاز یا کش‌بک خرید)
- **بدون قابلیت برداشت نقدی** — موجودی فقط به‌عنوان روش پرداخت/تخفیف در سفارش‌های بعدی در چک‌اوت ووکامرس قابل استفاده‌ست
- نمایش موجودی کیف‌پول در پروفایل مشتری و در چک‌اوت (به‌صورت گزینه پرداخت جزئی یا کامل)
- تاریخچه تراکنش‌های کیف‌پول (واریز/برداشت داخلی) برای مشتری و ادمین قابل مشاهده باشه
- باید سازگار با گزارش‌های مالی و مالیاتی ووکامرس باشه (کیف‌پول به‌عنوان کد تخفیف سفارش یا Fee منفی اعمال بشه، نه دستکاری مستقیم قیمت)

---

## ۴. سیستم سطح‌بندی مشتریان (Tiers)

- چند سطح قابل تعریف توسط ادمین (مثلاً برنزی/نقره‌ای/طلایی/الماسی — نام و تعداد سطوح آزادانه قابل تنظیم)
- **معیار ارتقا:** مجموع خرید کل دوره عضویت مشتری (Lifetime Value) — نه بازه زمانی محدود
- **بدون تنزل سطح** — مشتری هرگز به سطح پایین‌تر برنمی‌گرده
- هر سطح می‌تونه مزایای اختصاصی داشته باشه:
  - ضریب امتیازدهی متفاوت (مثلاً سطح طلایی ۱.۵ برابر امتیاز می‌گیره)
  - دسترسی به تخفیف‌های اختصاصی سطح
  - ارسال رایگان خودکار از سطح مشخصی به بالا
  - هدیه خوش‌آمدگویی هنگام ارتقا به سطح جدید
- نمایش بصری سطح (بج/آیکون/رنگ اختصاصی) در پروفایل و صفحه باشگاه مشتریان
- اطلاع‌رسانی خودکار هنگام ارتقای سطح (از طریق کانال‌های بخش ۶)

---

## ۵. مناسبت‌های خاص (تولد و سالگرد عضویت)

- ادمین از پنل مدیریت تعیین می‌کنه در تولد و سالگرد عضویت هر مشتری چه پاداشی داده بشه:
  - گزینه: کد تخفیف
  - گزینه: امتیاز هدیه
  - یا هردو، یا خاموش
- تاریخ تولد از پروفایل کاربر (فیلد اختیاری هنگام ثبت‌نام یا تکمیل پروفایل) گرفته بشه
- زمان‌بندی ارسال خودکار (Cron) نزدیک تاریخ مناسبت با پیام قابل سفارشی‌سازی

---

## ۶. سیستم معرفی دوست (Referral Program)

- هر مشتری یک **کد معرف اختصاصی** داره (قابل اشتراک‌گذاری با لینک یا کد)
- وقتی کاربر جدید با کد معرف ثبت‌نام/خرید می‌کنه، **هر دو طرف** امتیاز دریافت می‌کنن:
  - امتیاز برای معرف (Referrer)
  - امتیاز برای معرفی‌شونده (Referee) — مثلاً هنگام اولین خرید
- تعیین مقدار امتیاز هر طرف، شرط فعال‌سازی (فقط ثبت‌نام یا حتماً خرید هم لازمه)، و امکان محدودسازی سوءاستفاده (مثلاً یک IP/کاربر فقط یک‌بار از هر کد استفاده کنه) — همگی از پنل ادمین قابل تنظیم
- گزارش عملکرد معرفی برای هر مشتری (چند نفر معرفی کرده، چقدر امتیاز گرفته)

---

## ۷. اطلاع‌رسانی (Notifications) — چندکاناله

برای رویدادهای زیر باید سیستم اطلاع‌رسانی کامل (پیامک + ایمیل + اعلان داخل پنل کاربری) وجود داشته باشه:
- کسب امتیاز جدید
- نزدیک شدن به انقضای امتیاز (در صورت فعال بودن Expiry)
- ارتقای سطح (Tier Upgrade)
- دریافت هدیه تولد/سالگرد
- شارژ/مصرف کیف‌پول
- موفقیت در معرفی دوست

### الزامات فنی:
- **پیامک:** پشتیبانی از درگاه‌های ایرانی — Kavenegar، Mellipayamak، FarazSMS (قابل انتخاب و تنظیم API Key هرکدوم از پنل)
- **ایمیل:** استفاده از سیستم ایمیل داخلی وردپرس (wp_mail) با قالب‌های قابل ویرایش
- **اعلان داخلی:** بخش Notification Center در پنل کاربری مشتری (React) با نمایش Real-time/Polling
- همه قالب‌های پیام (پیامک/ایمیل) باید در پنل ادمین قابل ویرایش متن باشن (Placeholder-based، مثل {نام_مشتری}، {تعداد_امتیاز})

---

## ۸. رابط کاربری مشتری (Customer-Facing UI)

نمایش در **دو محل** (هر دو با React + Tailwind ساخته بشن، هیدریت‌شده روی صفحات وردپرس مثل معماری karasuno):

1. **تب اختصاصی داخل «حساب کاربری من» (My Account)** — خلاصه وضعیت: امتیاز فعلی، سطح فعلی، موجودی کیف‌پول، دسترسی سریع به تاریخچه
2. **صفحه/داشبورد مستقل باشگاه مشتریان** — نمای کامل‌تر شامل:
   - نمودار پیشرفت تا سطح بعدی
   - تاریخچه کامل تراکنش‌های امتیاز و کیف‌پول
   - لیست پاداش‌های قابل دریافت و امکان تبدیل امتیاز
   - کد و آمار معرفی دوست
   - مرکز اعلان‌ها

طراحی باید کاملاً راست‌چین (RTL)، فونت فارسی مناسب، و هماهنگ با هویت بصری Karasu باشه.

---

## ۹. پنل مدیریت (Admin Panel)

بخش ادمین (React + Tailwind، داخل wp-admin، مشابه ساختار karasu-woo-pannel) شامل تب‌های:

1. **داشبورد کلی:** آمار کلی باشگاه (تعداد اعضا، امتیاز اهدایی، نرخ تبدیل، محبوب‌ترین پاداش‌ها)
2. **تنظیمات امتیازدهی:** نرخ تبدیل خرید، امتیاز اکشن‌ها، تنظیمات انقضا
3. **مدیریت سطوح (Tiers):** تعریف سطوح، آستانه‌ها، مزایای هرکدوم
4. **مدیریت پاداش‌ها:** تعریف تخفیف/ارسال رایگان/هدیه/نرخ تبدیل کیف‌پول
5. **مناسبت‌های خاص:** تنظیم پاداش تولد/سالگرد
6. **معرفی دوست:** تنظیمات امتیاز و محدودیت‌ها
7. **کانال‌های اطلاع‌رسانی:** تنظیم API درگاه‌های پیامکی، قالب‌های پیام
8. **مدیریت اعضا:** جستجو/فیلتر مشتریان، مشاهده و ویرایش دستی امتیاز/کیف‌پول/سطح هر مشتری
9. **گزارش‌ها:** خروجی Excel/CSV از تراکنش‌ها و آمار

---

## ۱۰. الزامات فنی و معماری

- **بک‌اند:** PHP، کاملاً مطابق استانداردهای وردپرس/ووکامرس (Hooks، Custom Post Types یا جداول اختصاصی برای تراکنش‌های امتیاز/کیف‌پول، سازگاری کامل با **HPOS**)
- **فرانت‌اند:** React + Tailwind + Vite (بیلد جدا برای پنل ادمین و بخش مشتری)، دقیقاً مطابق الگوی فنی karasu-woo-pannel
- **ارتباط بین PHP و React:** REST API اختصاصی وردپرس (namespace مجزا، مثلاً `karasu-buyers-club/v1`) با احراز هویت nonce/JWT مطابق استاندارد وردپرس
- **دیتابیس:** جداول اختصاصی برای تراکنش‌های امتیاز، تراکنش‌های کیف‌پول، تاریخچه سطح، کدهای معرف — نه متا دیتای پراکنده
- **امنیت:** Rate limiting برای اندپوینت پیامک، Sanitization/Escaping کامل ورودی‌ها و خروجی‌ها، Nonce/Capability check روی همه اندپوینت‌های ادمین
- **بدون هیچ Kill-switch یا تله‌متری خارجی** — فقط اتصالات بیرونی شفاف و کاملاً تحت کنترل کاربر (مثل درگاه‌های پیامکی که خودش API Key وارد می‌کنه)
- سازگاری با چندزبانگی (حداقل فارسی کامل، ساختار آماده برای ترجمه با i18n وردپرسی)
- تقویم شمسی برای نمایش تاریخ‌ها (تولد، سالگرد، تاریخ انقضای امتیاز)

---

## ۱۱. خروجی مورد انتظار از این پرامپت

لطفاً بر اساس این مشخصات، مستندات زیر رو به سبک مستندسازی پروژه‌های قبلی (PRD, ARCHITECTURE, GUIDELINES, ROADMAP, CLAUDE.md) تولید کن، و سپس ساختار پوشه‌بندی افزونه و اسکلت اولیه کد (PHP bootstrap + Vite/React setup) رو پیاده‌سازی کن.
